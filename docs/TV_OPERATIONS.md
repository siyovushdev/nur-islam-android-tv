# Установка, настройка и восстановление

Этот документ описывает штатные возможности ПО. **Разрешённая функциональная проверка отдельного Debug-пакета на H728 описана в [аппаратном отчёте](H728_HARDWARE_REPORT.md). HOME, reboot/питание и 72 часа пока не прошли аппаратную приёмку.** До эксплуатации необходимы утверждённый календарь и аппаратная приёмка. Не назначайте приложение основным экраном, пока не проверили вход в настройки и способ возврата.

## Подготовка APK

Debug имеет package `dev.nurislam.tv.debug`, Release — `dev.nurislam.tv`, minSdk 26 (Android 8). Это разные приложения с отдельными файлами и настройками.

Release artifact unsigned. Владелец хранит постоянный release keystore вне репозитория; следующие обновления подписываются **тем же ключом**. Потеря ключа может потребовать переустановки с потерей приватных данных.

Пример на компьютере администратора (не выполняется автоматически):

```bash
keytool -genkeypair -keystore /secure/path/nur-islam-release.jks \
  -alias nur-islam -keyalg RSA -keysize 3072 -validity 10000
zipalign -p -f 4 app-release-unsigned.apk nur-islam-aligned.apk
apksigner sign --ks /secure/path/nur-islam-release.jks \
  --out nur-islam-release.apk nur-islam-aligned.apk
apksigner verify --verbose nur-islam-release.apk
```

Пароли вводите интерактивно, ключ и пароли не коммитьте. `zipalign`/`apksigner` находятся в Android SDK Build Tools. Подпись локального APK не публикует production-релиз.

После разрешения владельца установку/обновление на **выбранное тестовое устройство** можно выполнить:

```bash
adb -s DEVICE_SERIAL install -r nur-islam-release.apk
adb -s DEVICE_SERIAL shell am start -n dev.nurislam.tv/.MainActivity
```

Всегда задавайте `-s`: не устанавливайте на случайно подключённый рабочий ТВ. В рамках разработки установки на рабочий телевизор мечети не выполнялись.

## Пульт и ориентация

Пять отдельных нажатий OK за пять секунд открывают подтверждение входа. Затем DOWN → OK — настройки. MENU — альтернативный путь, необязательный. Возврат BACK, без PIN по умолчанию. Это предотвращает случайные изменения, но не заменяет контроль физического доступа.

В «Ориентация» выберите любой из пяти режимов напрямую. **Не поворачивайте только текст** средствами прошивки. Для панели, физически стоящей вертикально при системном landscape 1920×1080, попробуйте CW/CCW: должен быть читаем весь экран вместе с настройками. Выберите «Подтвердить и сохранить» за 15 секунд. По умолчанию выделена отмена. Неподтверждённый режим не записывается и отменяется по таймеру, BACK, уходу приложения в фон и пересозданию процесса/Activity.

AUTO опирается на окно и не определяет монтаж. UP/DOWN работают для пульта, который держат вертикально; редактор подписи использует все четыре направления и свою экранную клавиатуру, поэтому не зависит от поворота системной IME.

## Импорт календаря без сети и пересборки

1. Подготовьте JSON по [SCHEDULE_FORMAT.md](SCHEDULE_FORMAT.md) из **утверждённого мечетью** источника.
2. Настройки → Расписание → «Импорт JSON — выбрать файл». SAF работает с локальным хранилищем/USB, когда TV-прошивка предоставляет DocumentsProvider. Приложение не требует сетевых или storage-разрешений для выбранного документа.
3. Полностью проверяется файл до применения. При ошибке текущий календарь остаётся прежним.
4. В предпросмотре проверьте год, locationId, источник, revision, число дней, approved, смысл Фаджра и сравнение восьми значений на выбранную дату. Флаг approved — декларация файла, **не цифровая подпись источника**; подлинность подтверждает ответственный человек.
5. Подтвердите утверждение источника и отдельно применение. `approved=false` можно просмотреть, но применить нельзя.
6. Экран обновляется немедленно. Часы остаются и при отсутствии нужного года. Изменение названия/места в настройках не меняет часовой пояс и календарь.

Во время чтения можно вернуться BACK к табло: незавершённое чтение отменяется, открытый stream закрывается, поздний результат не применяется. Поведение чужого DocumentsProvider и USB всё равно следует проверить на целевой прошивке.

### Резервный путь без SAF

Если системный picker отсутствует или запрещён, приложение показывает сообщение и предлагает импорт из локальной папки. С компьютера администратора, после разрешения доступа ADB:

```bash
adb -s DEVICE_SERIAL shell mkdir -p /sdcard/Android/data/dev.nurislam.tv/files
adb -s DEVICE_SERIAL push approved-schedule.json \
  /sdcard/Android/data/dev.nurislam.tv/files/incoming-schedule.json
```

Для Debug подставьте `dev.nurislam.tv.debug`. Настройки → Расписание → «Импорт из локальной папки». Путь также показан в интерфейсе. **Никакого автоматического применения файла**: та же проверка, предпросмотр и подтверждение. Скопированный JSON не требуется после применения. Не удаляйте оригинал утверждённого календаря у ответственного.

Доступ ADB к app-specific external storage зависит от прошивки/политик. Если нет ни SAF/USB, ни разрешённого ADB, путь доставки файла является конкретным аппаратным ограничением; сетевой сервер в APK ради обхода не запускается.

### Замена, переход года и откат

Приватный `files/schedule-store.json` — один envelope с двумя полными поколениями и SHA-256 каждого канонического JSON. `AtomicFile`, синхронизация и проверка записи не публикуют половину календаря. Вся операция сериализована; StateFlow меняется после сохранения. При обнаружении испорченного текущего payload может использоваться проверенная предыдущая версия с видимым уведомлением и диагностикой.

Если ошибка возникла при завершении записи или проверке чтением, файл **мог уже обновиться**. Приложение сообщает об этом и оставляет на табло последнее проверенное состояние; оно не вызывает `failWrite()` после начала `finishWrite()` и не удаляет committed-файл. После устранения ошибки хранилища повторите операцию либо перезапустите процесс приложения для проверки и загрузки фактически сохранённых календарей.

Можно импортировать следующий год заранее: предыдущий **меньший** год используется только для своих полных дат, до перехода на новый. На границе двух имеющихся лет доступен следующий Фаджр с семантикой нового года. Хранятся два последних импорта; загрузка нескольких будущих лет подряд может вытеснить календарь текущего года — предупреждение предпросмотра нужно прочитать.

Откат требует подтверждения и меняет текущую/предыдущую версии местами. Если откатываются к более раннему году, будущий календарь из резервной версии **не используется автоматически**: это позволяет отвергнуть ошибочный будущий файл. Для отмены отката можно подтвердить обратный откат или импортировать исправленный источник. При отсутствии нужной даты — предупреждение, без переноса DD.MM между годами.

Сбой питания на реальной флеш-памяти, деградация накопителя и 72-часовой режим не подтверждаются одним unit-тестом: проверяйте оборудование отдельно.

## Штатный HOME и выход

Manifest содержит MAIN + HOME + DEFAULT, отдельно LEANBACK_LAUNCHER. **[Новый мастер установки без ADB](TV_SETUP.md)** запрашивает системную HOME-role (API 29+) или открывает настройки HOME / resolver, после возврата проверяет фактическое назначение. Device Owner нельзя получить обычным разрешением; он определяется по Android. Только при настоящих полномочиях предлагается проба Lock Task с автовыходом и отдельное подтверждение постоянного kiosk. Из BOOT_COMPLETED Activity не запускается: штатный запуск основан на выборе HOME.

Обычно после выбора HOME Android возвращает это приложение при Home/запуске системы, но TV-прошивка может ограничивать смену лаунчера или запуск после питания. Возврат HOME в уже работающий процесс закрывает настройки и показывает публичное табло. KEEP_SCREEN_ON действует для активного окна; fullscreen восстанавливается при фокусе. Системные ограничения, power-on-after-AC, заставка и HDMI-CEC проверяются на модели отдельно.

**Выход:** пять OK → настройки → «Основной экран HOME / безопасный выход»:

- «Мастер HOME / kiosk» → kiosk → «Отключить kiosk»; затем итоговая проверка → «Восстановить штатный Launcher» → подтвердите и назначьте штатный HOME в Android. Это снимает только созданную нашим приложением политику HOME и не снимает Device Owner.
- «Открыть другой лаунчер» — системный chooser исключает само табло; это разовый выход, настройка HOME при этом не меняется.

Если экран недоступен, после отдельного разрешения на управление устройством используйте ADB. Сначала определите установленный штатный компонент, не копируйте чужое имя пакета:

```bash
adb -s DEVICE_SERIAL shell cmd package query-activities \
  -a android.intent.action.MAIN -c android.intent.category.HOME
adb -s DEVICE_SERIAL shell cmd package set-home-activity STOCK_PACKAGE/STOCK_ACTIVITY
adb -s DEVICE_SERIAL shell am start -n STOCK_PACKAGE/STOCK_ACTIVITY
```

Наличие и синтаксис shell-команд проверьте через `cmd package help` на своей прошивке. Как аварийный путь можно остановить/отключить табло **после определения штатного HOME**; очистка данных/удаление APK уничтожит импорт и настройки. Эти действия на рабочем устройстве требуют решения администратора, автоматически не выполняются.

## Аппаратная приёмка перед мечетью

- Модель/Android/прошивка, подключение пульта, 720p/1080p/4K, настоящий portrait и физический монтаж CW/CCW, overscan и шрифты с 3–8 м.
- SAF/USB и резервный импорт, отказ/отмена/повреждённый файл, источники Фаджра и Иша, подтверждённый полный год и следующий год.
- Подтверждение/таймаут ориентации, выключение в процессе неподтверждённого поворота, сохранение всех настроек после 3+ холодных запусков.
- Отключение сети, изменение системных часов, sleep/resume, смена суток и года, восстановление источника после перезапуска.
- Выбор HOME, холодный запуск после reboot и AC loss, безопасный возврат к штатному лаунчеру, обновление APK тем же ключом.
- 72 часа непрерывной работы с журналом и перезагрузками. Яркость/режим панели и риск выгорания для статичного табло проверяются на конкретном дисплее.

Основания: [Android Custom Home apps](https://developer.android.com/work/dpc/dedicated-devices/cookbook), [Storage Access Framework](https://developer.android.com/training/data-storage/shared/documents-files), [AtomicFile](https://developer.android.com/reference/android/util/AtomicFile). Эти API не обещают одинакового поведения всех потребительских TV.
