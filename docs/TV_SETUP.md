# Первоначальная настройка с пульта, без ADB

Реализованный мастер — Kotlin / Jetpack Compose, доступен в Debug **и Release**. Он не требует компьютера для обычного выбора HOME на прошивках, где Android позволяет такой выбор. **Подтверждённых физических моделей пока нет.** Системные диалоги, QR enrollment, boot/питание и 72 часа работы нельзя считать проверенными по JVM-тестам.

## Обычная установка APK → HOME

1. Получите у установщика **подписанный Release APK** (`dev.nurislam.tv`). Подготовка подписи — в [TV_OPERATIONS.md](TV_OPERATIONS.md). CI выдаёт unsigned Release: его нельзя устанавливать до подписи. Debug (`dev.nurislam.tv.debug`) — отдельное тестовое приложение; не используйте его для постоянного provisioning.
2. На согласованном тестовом ТВ откройте APK с USB через штатный файловый менеджер/установщик. Разрешите установку из этого источника, если это предусмотрено прошивкой; после установки отзовите разрешение. Можно использовать разрешённый производителем способ доставки APK. Компьютер и ADB не обязательны; если TV не имеет установщика, используйте инструкцию производителя.
3. Откройте «Нур Ислам» в списке приложений. Мастер проверит Android/API, фактический обработчик HOME, доступность HOME-role, Device Owner нашего APK, разрешение DPC и состояние Lock Task. Неудачная диагностика не даёт полномочий.
4. При необходимости выберите «Экран, тема и расписание»: для физически вертикального ТВ с окном 1920×1080 выберите CW/CCW и подтвердите за 15 секунд. Настройте имя, язык и импортируйте утверждённый JSON. Вернитесь в мастер: **OK пять раз за пять секунд → Открыть настройки администратора → Основной экран HOME / безопасный выход → Мастер HOME / kiosk**.
5. «Далее: основной экран» → «Сделать Нур Ислам главным экраном». На Android 10+/API 29+ используется системный запрос `ROLE_HOME`, когда роль доступна. Иначе открываются настройки HOME; при отсутствии — обычный HOME resolver. Выберите «Нур Ислам» и «Всегда», если Android предлагает такой выбор.
6. После возврата мастер повторно проверяет **реальный HOME resolver**, а не доверяет `RESULT_OK`. Если назначение не произошло, попробуйте «Настройки HOME Android». Отказ или закрытая прошивка не блокируют приложение: можно пропустить мастер и пользоваться обычным полноэкранным табло.
7. Без Device Owner / allowlist пропустите kiosk. На последнем шаге проверьте возврат к табло настоящим HOME и завершите мастер. Завершение сохраняется; мастер не появляется при каждом запуске, но доступен из настроек.
8. Сохраните резервную копию исходного календаря. На целевой модели проверьте HOME, три перезагрузки, потерю питания, сон, заставку, HDMI-CEC и 72 часа. Штатный HOME обычно запускается Android после boot, но прошивка может это менять. Приложение не обходит ограничения фонового запуска и не включает питание панели.

Все страницы прокручиваются с ↑/↓; OK выполняет действие, BACK отменяет/возвращает назад. Не нужны MENU, мышь, системная клавиатура или сенсор. Эти же страницы поворачиваются вместе с табло в CW/CCW.

## Настоящий kiosk на управляемом устройстве

**Device Administrator ≠ Device Owner.** Обычная установка на уже настроенном Android не может выдать DO кнопкой «Разрешить». Приложение не предлагает активацию legacy device admin как замену DO и не вызывает factory reset.

Два поддерживаемых программных варианта:

- Наш APK уже штатно provisioned как **Device Owner**: после отдельного согласия мастер добавляет только свой пакет в allowlist, сохраняя остальные. Можно отдельно назначить managed HOME. Политики HOME и добавление своего пакета отмечаются в приватных настройках, чтобы при выходе снимать только созданные нами изменения.
- Другой DPC уже разрешил `dev.nurislam.tv` через `setLockTaskPackages`: наше приложение может запускать/останавливать собственный Lock Task, но не меняет allowlist, HOME-policy и полномочия этого DPC. Если политика не даёт выйти или сменить HOME, требуется управляющий администратор.

В мастере → HOME → kiosk:

1. «Проверить безопасный выход». Система должна подтвердить `LOCK_TASK_MODE_LOCKED`. Без `isLockTaskPermitted` вызова `startLockTask` нет; обычное screen pinning не считается kiosk. Нельзя начинать новую пробу поверх существующего закрепления/Lock Task.
2. В течение 20 секунд выберите ↓ → «Завершить пробу с пульта» → OK. Приложение останавливает Lock Task и проверяет `NONE`. BACK/таймаут/уход в фон отменяют пробу. Отмена не разрешает постоянное включение.
3. Только после успешной пробы доступно «Включить kiosk при запуске» → отдельное подтверждение (по умолчанию выбрана отмена). В постоянном режиме сохраняется согласие администратора; при следующем запуске полномочия проверяются вновь. При отзыве разрешения авто-kiosk отключается, на табло появляется причина.
4. Незавершённая проба помечается **до** запуска Lock Task. После прерывания процесса на следующем запуске приложение сначала пытается выйти; это не превращается в постоянное согласие. Если Android отказывает в выходе, marker сохраняется для повторной попытки, восстановление kiosk отключено. Приложение не может гарантировать восстановление в момент падения ОС/прошивки.

**Выход всегда доступен с пульта:** OK ×5 → настройки → HOME → мастер → HOME → kiosk → **«Отключить kiosk»**. Сначала снимается сохранённый автозапуск kiosk, затем останавливается задача и проверяется результат. Удаляется только добавленная нами allowlist-запись; чужая allowlist остаётся. Не устанавливаются user restrictions, блокировки кнопок питания, пароль или запрет настроек. Пять OK защищают от случайных нажатий, **не аутентифицируют** человека; доступ посетителей к пульту надо ограничить организационно.

## Восстановление штатного Launcher

Мастер → итоговая проверка → «Восстановить штатный Launcher» → подтвердить. Сначала отключается kiosk, затем снимается только созданная нами persistent HOME-policy и обычное предпочтение нашего пакета. Открываются системные настройки HOME; выберите штатный Launcher и «Всегда». Если настройки отсутствуют, приложение пробует обычный системный HOME intent. Это **не** обещает универсальное снятие HOME-role на закрытой прошивке: проверьте фактический результат и назначьте Launcher средствами производителя. Другой DPC может переустанавливать свою политику — обращайтесь к его администратору.

Простое «Открыть другой лаунчер» в старом меню — разовый запуск, **не** изменение HOME. Сначала отключите kiosk. Не удаляйте/не очищайте данные приложения, пока не проверили штатный HOME: это уничтожает календарь, настройки и учёт собственных политик. Device Owner при обычном выходе **остаётся** — снятие управления/сброс выполняется администратором по правилам производителя отдельно. Приложение не вызывает deprecated `clearDeviceOwnerApp` и не удаляет чужие политики.

## Первоначальный managed provisioning без ADB

Это инструкция **для установщика и совместимой прошивки**, а не универсальный шаг после скачивания APK. Конкретная модель и её firmware пока не предоставлены/не проверены. **Не сбрасывайте рабочий ТВ для эксперимента.** Наличие Android 12+/RoleManager или положительный `isProvisioningAllowed` само по себе не подтверждает поддержку QR.

| Устройство / состояние | Доступный путь |
| --- | --- |
| Обычный уже настроенный Android TV, смена HOME разрешена | APK → мастер → системный HOME; без DO, kiosk недоступен до разрешения DPC |
| HOME-role отсутствует, но есть настройки HOME / resolver | Системный выбор HOME с проверкой результата; зависит от производителя |
| HOME и managed setup закрыты производителем | Обычное табло; нужен поддерживаемый производителем способ. Root/Accessibility/ADB-обходов в APK нет |
| API 26–30, **не настроен**, Android сейчас допускает provisioning, есть системный handler | Мастер показывает отдельный подтверждаемый запуск `ACTION_PROVISION_MANAGED_DEVICE` **for result**. Полномочия проверяются по завершении |
| API 31+ с подтверждённым managed setup wizard | QR/другой enrollment производителя при первоначальной настройке; из обычного APK deprecated intent **не запускается** |
| Уже управляется внешним DPC/EMM | Администратор устанавливает APK, разрешает пакет для Lock Task и при необходимости назначает HOME |

### Порядок для совместимой модели

1. До каких-либо сбросов получите инструкцию производителя именно для модели/firmware: поддерживает ли **fully managed / dedicated device**, как открыть enrollment с пульта, нужен ли сканер/камера, сеть, аккаунт или EMM. Типовой QR flow обычного Android со многократным касанием приветственного экрана **нельзя переносить на любой TV**. Если производитель не предоставляет доступный путь — остановите managed enrollment, оставайтесь в обычном HOME.
2. Подготовьте подписанный Release APK с постоянным ключом. Для QR загрузки установщик предоставляет доступную устройству HTTPS-ссылку на **тот же** APK и URL-safe Base64 SHA-256 checksum файла. APK не публикуется этим PR. QR генерируется установщиком из следующего шаблона; заполнители обязательно заменить:

   ```json
   {
     "android.app.extra.PROVISIONING_DEVICE_ADMIN_COMPONENT_NAME": "dev.nurislam.tv/dev.nurislam.tv.setup.MosqueDeviceAdmin",
     "android.app.extra.PROVISIONING_DEVICE_ADMIN_PACKAGE_DOWNLOAD_LOCATION": "https://YOUR-APPROVED-HOST/nur-islam-release.apk",
     "android.app.extra.PROVISIONING_DEVICE_ADMIN_PACKAGE_CHECKSUM": "URL_SAFE_BASE64_SHA256_OF_SIGNED_APK",
     "android.app.extra.PROVISIONING_LEAVE_ALL_SYSTEM_APPS_ENABLED": true
   }
   ```

   Checksum рассчитывают **после подписи**; SHA-256 hex-строка не подходит. Пример подготовки на компьютере установщика (не команда на ТВ): `openssl dgst -sha256 -binary nur-islam-release.apk | openssl base64 -A | tr '+/' '-_' | tr -d '='`. JSON/QR не содержит Wi-Fi паролей. Установщик может подготовить QR/USB заранее; администратор у совместимого ТВ выполняет только штатные шаги. Zero-touch допускается лишь если конкретное устройство зарегистрировано у поддерживаемого поставщика/EMM; наш APK не получает сам регистрацию EMM и не подменяет Android Device Policy.
3. Сохраните календарь, настройки ТВ и данные других приложений. **Только после отдельного согласования** администратор вручную выполняет необходимый заводской сброс по инструкции производителя. Приложение не вызывает wipe. Внимание: сам Android managed provisioning может сбросить устройство при ошибке enrollment — об этом предупреждает и подтверждение legacy flow в мастере.
4. В начальном setup wizard производителя запустите подтверждённый enrollment и передайте QR/пакет предусмотренным им способом. Подтвердите системное предупреждение об управлении устройством. Не завершайте обычную пользовательскую настройку вместо managed enrollment, если прошивка требует enrollment до её окончания.
5. На Android 12+ системный provisioning вызывает наши защищённые `GET_PROVISIONING_MODE` и `ADMIN_POLICY_COMPLIANCE` Activity. Принимается только fully managed mode из переданного Android списка. Work profile не поддерживается. Compliance возвращает успех только при фактическом `isDeviceOwnerApp`. Системные приложения сохраняются, HOME/kiosk автоматически **не включаются**. На старых версиях предусмотрен `DeviceAdminReceiver` callback завершения.
6. После завершения системной настройки откройте APK с пульта. Проверьте «Device Owner: да», реальный HOME и разрешение Lock Task. Пройдите пробу выхода и только затем сохраните kiosk. Если DO не подтверждён — не продолжайте блокировку; обратитесь к установщику/производителю.
7. На отдельном тестовом устройстве проверьте выход, восстановление Launcher, повторный запуск, boot и питание. Только затем согласовывайте установку на рабочий ТВ мечети. Запишите модель/firmware/способ enrollment в аппаратный протокол Issue #6; пока таких подтверждений нет.

### Основания Android API

- [HOME role / RoleManager](https://developer.android.com/reference/android/app/role/RoleManager) — API 29+, availability и запрос системного согласия.
- [Managed provisioning и изменения Android 12](https://source.android.com/docs/devices/admin/provision) — только initial setup, mode/compliance hooks.
- [DevicePolicyManager](https://developer.android.com/reference/android/app/admin/DevicePolicyManager) — `isProvisioningAllowed`, deprecated legacy intent, риск системного reset при ошибке.
- [Lock Task](https://developer.android.com/work/dpc/dedicated-devices/lock-task-mode) — allowlist, различие с screen pinning, остановка своей задачи.
- [Dedicated HOME](https://developer.android.com/work/dpc/dedicated-devices/cookbook) — persistent preferred activity при полномочиях DPC.
