# Календарь мечети

Один JSON хранит икамат, Джума, Рамадан и события конкретной мечети. Он не содержит
и не меняет таблицу времён намазов. Пример: `data/examples/mosque-calendar-DEMO.json`;
совместимое вымышленное расписание: `data/examples/prayer-schedule-DEMO-2026.json`.
Оба файла предназначены только для демонстрации, даты в них не являются решениями мечети.

## Обязательные поля

- `type`: `mosqueCalendar`.
- `schemaVersion`: `1`.
- `mosque`: `id` (стабильный идентификатор мечети), `name`, `cityId`, `city`, `timezone`.
- `validFrom`, `validUntil`: включительные местные даты `YYYY-MM-DD`, период не более пяти лет.
- `source`, `revision`: справочное описание происхождения и версии файла.

Идентификаторы состоят из строчных латинских букв, цифр, `_`, `-`, до 80 символов.
Часовой пояс — именованный IANA, например `Europe/Kaliningrad`, `Europe/Moscow`,
`Asia/Yekaterinburg`, `Asia/Vladivostok`, `Asia/Kamchatka`. Времена — местные `HH:mm`.
Приложение не прибавляет смещение к введённым значениям.

`demo: true` помечает документ как демонстрационный. Явные TEST/ТЕСТ/DEMO в источнике
также включают маркировку. TV и телефон обрабатывают эти данные одинаково. Программа
не удостоверяет источник и не требует `approved`. Не добавляйте это поле в новый формат.

## Необязательные разделы

`iqamah.rules` — список правил. `prayer`: `FAJR`, `DHUHR`, `ASR`, `MAGHRIB`, `ISHA`, `JUMUAH`.
`from` — начало действия. Последнее правило с подходящей датой заменяет более раннее.
`until` — последний день действия; после него более старое правило НЕ возвращается.
Для нового сезона добавьте правило с новой датой `from`. `exception: true` действует
только в день `from`, имеет приоритет над регулярным правилом и не допускает `until`.

- `mode: OFF`: отключено, без `time`/`minutes`.
- `mode: FIXED`, `time: HH:mm`: отдельное точное время икамата.
- `mode: OFFSET`, `minutes: 0..720`: интервал после явно известного начала из расписания.

Джума используется по пятницам вместо правил икамата Зухра. Её собственное начало
можно указать в `start: HH:mm`; для OFFSET оно обязательно. JSON-время Зухра не
подменяет начало Джума. Строка Зухра в исходном расписании сохраняется; активная
Джума показывается отдельно.

Фаджр старого файла с неуточнённым смыслом допускает FIXED, но не OFFSET. Для FIXED
без известного начала показывается отдельное время и наступление икамата, без вымышленного
отсчёта от азана. Достоверное начало Фаджра задаётся в расписании через `fajrMeaning: PRAYER_START`.

Проверяются пересечения икаматов и следующие достоверные начала молитв, в том числе
когда для следующей молитвы нет правила икамата. Значения автоматически не исправляются.
При неизвестной границе сведения доступны в диагностике. `iqamah.dimMinutes: 0..60`
необязателен; 0 означает без затемнения, индикация наступления длится одну минуту.

`ramadan` — список объектов с `firstFast` (первый гражданский день поста) и необязательным
`eid` (дата Ураза-байрама, через 29 или 30 дней). Без `eid` приложение не выдумывает
окончание и не показывает 30-й день как достоверно установленный день поста.

`events` — до 366 событий: уникальный `id`, `title`, необязательный `titleTatar`,
`from`, необязательный `until`, необязательные `start`/`end`. Даты включительные;
время показа действует ежедневно в указанном диапазоне, начало включительно, конец
исключительно. Без часов событие показывается весь день. Для интервала через полночь
нужны две записи. Дата события не вычисляется из названия или лунного календаря.

Все даты разделов должны лежать в периоде документа. Неизвестные поля, дубликаты,
неверные типы, повреждения и JSON больше 1 МиБ отклоняются.

## Применение и совместимость

Выбор файла автоматически определяет расписание или календарь мечети. Предпросмотр
показывает место, пояс, период и наличие разделов; подробности открываются по желанию.
Одно «Применить» заменяет весь календарь; отсутствующий раздел означает «не настроен».
Тема, поворот, масштаб и времена намазов сохраняются. Предыдущий документ доступен
в «Настройки → Загруженные данные → Вернуть предыдущий календарь мечети».
Оба поколения сохраняются одной атомарной записью с проверкой целостности.

Для расписания версии 2 должны совпадать идентификаторы мечети и города и часовой пояс.
Старое расписание версии 1 может быть общегородским: совпадают `locationId` и `cityId`
и часовой пояс. Такой файл не доказывает принадлежность конкретной мечети; её задаёт
выбранный дополнительный календарь. Для Казань XLSX `cityId` равен `kazan`.

При смене места или несовместимом годе календарь остаётся сохранён, но не исполняется.
Возврат совместимого расписания снова позволяет его использовать. Импорт следующего
года сохраняет работу предыдущего года, пока его расписание остаётся в резерве.
Рамадан и события могут отображаться без таблицы намазов; икамат требует расписание.
Ручные настройки прежних версий остаются доступными для специалиста до первого импорта
нового календаря; отсутствующие разделы нового файла не подменяются прежними настройками.
