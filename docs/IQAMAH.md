# Икамат: настройка и проверка (Issue #15)

Реализовано на Kotlin/Compose в TV и PhoneDebug. Расписание JSON не изменяется: начало/колонка исходного календаря и икамат — разные данные. По умолчанию функция выключена, правила пусты, затемнение выключено. Сервера и интернет не нужны.

## Настроить

Откройте **Настройки → Икамат** (TV: MENU или пять коротких OK → настройки администратора). Пальцем нажимайте строки и прокручивайте список. На TV используйте ↑↓/OK/BACK; цифровая клавиатура приложения доступна с D-pad. Сохранить/отменить доступны под списком.

1. Включите функцию, укажите источник правил — решение/протокол администрации. Только после настоящего согласования отметьте **Правила утверждены мечетью**. Любое изменение снимает это подтверждение. Debug/PhoneDebug допускают явно обозначенную демонстрацию без утверждения; **Release такие правила не исполняет**. Источник со словом «ТЕСТ», TEST, DEMO и т.п. нельзя отметить утверждённым.
2. Выберите один из пяти намазов. Строка показывает действующее сегодня правило. Новая запись задаётся с даты **YYYYMMDD** (например, `20261024`), действует до следующего изменения этого намаза. Так задаются сезонные изменения/Рамадан — ничего не меняется автоматически по сезону. Для одного дня включите **Разовое исключение**; на следующий день снова действует обычное правило.
3. Режим: **Отключено**, **Точное время** (ввод HHmm, например `1630` → `16:30`) или **После начала** (вручную введённые минуты 0–720). Это предел ввода, а не рекомендуемый религиозный интервал. Значение не подставляется автоматически.
4. Для относительного режима обязательно подтвердите смысл конкретного базового поля. Подтверждение связано с SHA-256 **полного файла календаря**, включая revision/source. Для точного времени такое подтверждение необязательно: без него начало остаётся неизвестным. Фаджр допускает относительный режим только при `fajrMeaning=PRAYER_START` **и** отдельном подтверждении поля. Само `fajrInMosque` / «Мәчеттә укыла» азаном не считается. Не изменяйте семантику JSON ради включения интервала.
5. **Добавить в черновик** ещё не пишет на диск. Задайте остальные намазы, откройте обзор **Сегодня: начало / икамат / правило**, проверьте источник и даты. **Сохранить → Подтвердить сохранение** применяет весь набор сразу. Отмена требует подтверждения потери черновика. В списке дат можно редактировать/удалить конкретную запись и затем сохранить. Изменение даты создаёт запись на новой дате; старую удаляйте явно, если она больше не нужна.
6. Для пятницы используется только отдельная **Джума (пятница)** с точным временем. Зухр не подставляется автоматически. Без отдельной записи пятничный икамат не настроен. Для субботы снова применяется обычный Зухр. Неизвестное начало Джума не объявляется азаном.

Время раньше подтверждённого начала или после полуночи не переносится/исправляется — событие блокируется с диагностикой. Времена JSON и введённые интервалы не округляются. Проверяются порядок пяти молитв (с отдельной Джума в пятницу) и пересечения окон ожидания/индикации, включая затемнение и переход полуночи. Равные или обратные времена икамата, ожидание следующей молитвы до окончания предыдущего окна — конфликт. Дополнительно икамат и его индикация проверяются по последующим началам молитв из применённого JSON, **даже если для них нет правила икамата или оно выключено**. Например, Джума 15:27 при Асре 15:15 блокируется; икамат Зухра 15:14 с индикацией до 15:15 допустим. Для границ используется существующий контракт проверенного календаря: Зухр/Аср/Магриб/Иша — начала молитв; Фаджр — только при `PRAYER_START`. Это не отменяет отдельного подтверждения базы для относительного режима икамата. Время Зухра в пятницу не подменяет неизвестное начало Джума. Если следующая граница неизвестна (включая `UNCONFIRMED` Фаджр или отсутствующий следующий год), её не выдумывают: предупреждение показывается перед сохранением, в обзоре дня и на табло. Само предупреждение о неизвестной границе не блокирует корректные ручные правила; доказанный конфликт блокирует. Включённый конфликтующий набор нельзя сохранить: подтверждение заблокировано, показаны названия, даты и введённые времена. Проверка выполняется и в ViewModel, по всем доступным текущим и будущим датам календаря, включая сезонные правила и исключения. Истёкшие конфликты не мешают исправлению правил с новой даты: историю удалять не требуется. Если календаря ещё нет, проверка выполняется при его появлении. Новые календарные данные, старый файл или откат могут выявить конфликт: на затронутые даты **весь икамат приостанавливается**, на табло постоянно показана диагностика; обычное расписание работает. Значения не исправляются автоматически. Функцию всегда можно явно выключить и сохранить черновые значения для последующего исправления.

## Табло и надёжность

- До подтверждённого начала — прежний отсчёт намаза и отдельная подпись ближайшего икамата. После начала — крупный **До икамата**, название, HH:mm и секундный отсчёт. Если начало неизвестно, отдельное фиксированное время показывается без ложного отсчёта от азана.
- Пока активны **До икамата** или **Икамат**, выделена соответствующая строка. После окончания индикации/затемнения выделение возвращается к следующему началу молитвы. Джума получает отдельную строку **Джума (пятница) · Икамат** с её точным временем; строка Зухра и её время из JSON сохраняются. Для продолжающейся после полуночи индикации также показывается отдельная строка икамата с исходной датой, чтобы не выделять время сегодняшней молитвы вместо вчерашней.
- На наступлении — **Икамат** на 60 секунд, затем следующее событие. Никакого мигания/звука. Можно явно задать спокойное затемнение 1–60 минут; оно не блокирует доступ к настройкам и не меняет время молитвы.
- На телефоне демонстрация постоянно обозначена баннером **ТЕСТОВЫЙ ИКАМАТ**; карточка события содержит ТЕСТ и на TV. Тестовый календарь также делает событие демонстрационным и блокируется движком Release.
- Правила отдельно сохраняются в `files/iqamah-store.json`: версия схемы 1, SHA-256, Android AtomicFile, текущая/предыдущая версия. Изменение календаря не переписывает правила. Импорт сообщает о необходимости проверки совместимости. При несовпадении полного файла относительные правила приостанавливаются до нового подтверждения базы; отдельные фиксированные времена сохраняются, но без старого подтверждения начала. Проверьте их применимость на новый год вручную.
- В редакторе есть подтверждаемый откат предыдущего сохранения. При ошибке до commit остаётся старое состояние. При неопределённой проверке после commit перечитывается фактическое хранилище, выводится предупреждение, повторный failWrite не выполняется. Повреждённая текущая версия восстанавливается из проверенной резервной с предупреждением; если обе недоступны — функция отключена, показана ошибка.
- Без календаря/даты/правила таймер не выдумывается. Часовой пояс табло — Europe/Moscow. Скачок часов относительно монотонного времени более двух минут в работающем процессе блокирует индикацию до действия **Часы проверены**. Приложение не меняет системное время и не может офлайн доказать правильность правдоподобных часов после холодного запуска: это проверяется администратором в Android. Пропущенные события не проигрываются задним числом.

## Личная проверка на телефоне

1. Установите подписанный **Nur-Islam-Phone-Debug.apk** из `nur-islam-phone-debug` окончательного зелёного CI этого PR (GitHub требует вход; ZIP нужно распаковать). Откройте APK файловым менеджером, разрешите установку этому менеджеру при запросе Android. Приложение появится как «Нур Ислам · Телефон (тест)», пакет `dev.nurislam.tv.phone.debug`; HOME/DPC/kiosk отсутствуют. Совместимость с предыдущим APK проверяется отдельно по сертификату, см. отчёт PR.
2. Импортируйте свой валидный годовой **тестовый** JSON (`approved=true` означает техническую готовность файла к импорту, а не реальное утверждение тестовых данных). Подтвердите именно предупреждение о демонстрации. Значения восьми строк должны точно совпасть с файлом.
3. Для безопасной демонстрации в редакторе включите икамат, источник **ТЕСТ ДЛЯ ТЕЛЕФОНА**, оставьте утверждение выключенным. Задайте одному намазу отдельное фиксированное время через 2–3 минуты по **московским часам табло**, дату сегодня, базу не подтверждайте. Сохраните с подтверждением, вернитесь: баннер ТЕСТ постоянен, ложного «До икамата» нет. Дождитесь надписи «Икамат», через минуту она исчезнет. Это сценарий тестирования UI, **не правило мечети**.
4. Для проверки секундного отсчёта используйте только синтетический календарь с явно подтверждённой тестовой семантикой начала: задайте своё тестовое значение интервала, подтвердите поле, дождитесь начала → «До икамата» → «Икамат» → следующего события. Реальный JSON/Фаджр ради демонстрации не редактируйте. Сезон/исключение проверяются через обзор выбранных правил и автоматические тесты без изменения часов рабочего ТВ.
5. Закройте и откройте приложение: правила и баннер восстановятся. Проверьте обе темы, три масштаба, AUTO/portrait/landscape/CW/CCW, сохранение/отмену, откат. Затем отключите демонстрационную функцию.

## Выполненные программные проверки и доказательства

Pure JVM: обратный/равный порядок и пересечения окон, будущие исключения/пятница/полночь/новый год, сохранение введённых значений; все пять намазов/режимы, неподтверждённый Фаджр, отдельная пятница, даты/сезоны/исключения, граница суток/года, отсутствие данных, неверные значения, смена календаря, часы, запись/commit verification/recovery/restart/rollback. Robolectric: framework AtomicFile на API 26/29/30/31/34/35; Compose касания, ввод D-pad, подтверждение базы, валидация/отмена/удаление/сохранение, действительный ViewModel/хранилище телефона. Матрица табло: обе темы, portrait/landscape/CW/CCW, масштабы 85/100/115%; прежняя матрица 720p/1080p/4K продолжает выполняться.

CI собирает Debug/Release/PhoneDebug и androidTest APK, выполняет все unit/Compose Robolectric тесты и lint. Отдельный job устанавливает **именно опубликованный APK** на одноразовый Android API 35 emulator, проходит касаниями импорт/редактор/сохранение, холодный рестарт процесса и реальное ожидание наступления/завершения индикации. Это Android emulator, **не физический телефон/TV**.
