Установлен только проверенный отдельный APK **dev.nurislam.tv.debug**, version 0.2.0-demo. Другие APK/приложения не обновлялись. Исходники находятся в отдельном репозитории Nur Islam. Release собран unsigned, на приставку не устанавливался. Физическая TV-панель/монтаж и радиоканал пульта дистанционно не проверены: ввод — настоящие Android D-pad key events через ADB.

## Исправленные дефекты

### Межстрочный интервал меню

На реальном окне 960×540 dp меню уменьшает fontSize, но наследовало фиксированный Material bodyLarge lineHeight=24sp. При density 320 строки описаний с размером 12sp занимали **48 px вместо естественных 28 px**. Мастер/настройки чрезмерно растягивались, возрастал объём прокрутки. Прежние рендеры mdpi этого не обнаруживали.

В существующей теме сброшен только унаследованный фиксированный межстрочный интервал; используются метрики выбранного шрифта. Бизнес-логика, расписание, системные политики и архитектура не изменены. `TvDensityUiTest` воспроизводит реальную плотность, многострочный мастер и настройки обеих тем в landscape/CW/CCW. Тесты падают на исходном main и проходят после исправления. Обновлённый Debug APK повторно проверен на H728, [до/после и реальные экраны](../design/screenshots/h728/README.md).

### Уменьшение шрифтов после живой смены темы

На H728 после Elegant → Classic некоторые подписи и времена оказывались примерно вдвое мельче, чем после холодного запуска с теми же настройками. Переключение работало без обрезки, но ухудшало читаемость; первоначальный геометрический PASS сам по себе не покрывал этот дефект. Состояние измерения TextAutoSize сохранялось в визуальном поддереве при смене typeface или границ автоподбора после изменения масштаба.

В PrayerBoardScreen добавлен Compose key по appearance, масштабу текста и типу макета: при смене оформления, масштаба или типа макета пересоздаётся только визуальное поддерево. Часы, настройки и календарь остаются снаружи, перезапуск Activity/процесса не требуется. На H728 повторный живой переход показывает правильные крупные шрифты. Новый тест сравнивает метрики свежего и переключённого Classic с циклом масштабов на API 34/35; сам vendor-специфичный дефект воспроизводится на H728, но не на Robolectric. Аппаратные снимки до/после — основной источник доказательства исправления.

Instrumentation APK собран, **на приставку не устанавливался**. Аппаратные результаты в таблице получены непосредственно на H728, не из Robolectric. ## Наблюдения производительности

В Debug холодный запуск занимал около 4 секунд; logcat фиксировал пропуски кадров при старте. Во время раннего прогретого интерактивного прогона Debug gfxinfo показывал p50 около 150 мс / p95 около 200 мс. Это медленнее бюджета 60 Hz; плавность и ресурсопотребление оптимизированного подписанного Release **не сертифицированы**. Такие цифры Debug не выдаются за эксплуатационный норматив. В собранных app-scoped logcat нет сигнатур FATAL EXCEPTION / Fatal signal / ANR; во время выполненных сценариев падений не наблюдалось. Длительный soak-тест не заменяется кратким функциональным прогоном.

## Итоговое состояние устройства

Метаданные версий/путей/времени установки FamilyTV и его тестового пакета совпали с исходными. Из установленных пакетов добавлен только dev.nurislam.tv.debug; другие приложения не удалялись/не обновлялись/не останавливались. Штатный HOME и его роль сохранены, Lock Task = NONE, Device Owner и Device Administrator нашего приложения не назначены. Упоминание нашего пакета в списке установленного ПО кеша DPM **не является** назначением администратора.

Debug оставлен установленным, но **остановлен** после сеанса, чтобы не занимать экран и не удерживать KEEP_SCREEN_ON. В его собственных данных остался синтетический календарь A, имя «ТЕСТ», Elegant/landscape/100%, оба языка. Созданные входные JSON/UI-dump файлы на приставке удалены. Сырые logcat, meminfo/gfxinfo, policy/package snapshots остаются в приватном локальном каталоге вне Git; в репозитории только проверенные PNG нашего UI и обезличенный протокол. SHA-256 собранного APK сравнен с установленным APK.

## Следующий этап — только после отдельного разрешения

1. На согласованном тестовом устройстве временно выбрать Nur Islam HOME через системную UI; записать исходный Launcher, проверить HOME и возврат, затем восстановить исходный Launcher и роль с повторной диагностикой. Никаких привилегий Device Admin/DO для этого не нужно.
2. Отдельно разрешить 3 штатные перезагрузки; после каждой проверить запуск, настройки/календарь, пульт и безопасный выход. Отдельно согласовать простой FamilyTV на время проверки.
3. Для обновлений без компьютера отдельно проверить USB/подходящий DocumentsProvider: текущий системный SAF застревает на пустом списке при D-pad. Не устанавливать сторонний файловый менеджер без разрешения. Отдельно согласовать standby, отключение сети, физическое питание/AC/HDMI-CEC; эти действия требуют участия владельца оборудования. Проверить overscan и чтение с рабочего расстояния на фактической панели.
4. Для полного kiosk нужен настоящий allowlist/DPC. На этой настроенной приставке DO отсутствует. Не получать его обходом или сбросом FamilyTV-устройства. Managed provisioning/Lock Task проверять на отдельном совместимом чистом устройстве либо в согласованной существующей DPC-конфигурации с проверенным выходом.
5. После утверждения официального календаря и подписи Release — аппаратная проверка этого APK, затем **фактически выполненный 72-часовой прогон** с журналом uptime/ошибок/питания. Смена суток/года/часов в текущем аппаратном сеансе не симулировалась системными настройками.

**Полная аппаратная приёмка и готовность к эксплуатации пока не объявляются.** Этот этап покрывает разрешённую функциональность отдельного Debug-пакета; HOME, reboot, питание, kiosk, реальный offline и 72 часа остаются отдельными воротами приёмки Issue #6.
