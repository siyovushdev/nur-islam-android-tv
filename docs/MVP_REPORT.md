# Программный MVP — результат и границы приёмки

Дата: 23 октября 2026. Ветка: `codex/native-tv-mvp`, от `main` после PR #8. Задача: [Issue #9](https://github.com/siyovushdev/nur-islam-android-tv/issues/9). Версия ПО: 0.2.0.

**Результат: программный MVP реализован и проверен в доступной среде. Это не акт допуска к эксплуатации в мечети.** Утверждённый календарь и физический ТВ не предоставлены; установка на рабочий ТВ, Device Owner/kiosk, merge и production-релиз не выполнялись.

## Что работает

| Требование | Реализация и проверка |
| --- | --- |
| Elegant / Classic | Один Compose-экран и движок данных, разные палитра, шрифт, декор, порядок даты и оформление строк. Мгновенная смена и сохранение. |
| Все варианты TV | AUTO, native portrait, landscape, CW/CCW; перестановка размеров до поворота. Табло, настройки и встроенная клавиатура поворачиваются вместе. |
| Release-настройки | Пять OK за 5 секунд → подтверждение входа. D-pad/BACK без MENU/тачскрина/системной клавиатуры. Тема, ориентация, масштаб, языки табло, подписи, расписание, диагностика, HOME. |
| Безопасная ориентация | Прямой выбор режима, предпросмотр и 15 секунд на подтверждение; отмена выбрана изначально. Только подтверждённый режим сохраняется. Таймаут/BACK/фон/recreate возвращают прежний. |
| Локальный JSON | Полный год, строгое чтение UTF-8/JSON, 365/366 дат, уникальность, поля/типы, HH:mm, timezone, метаданные, размер/глубина. Нет частичного применения. |
| Импорт без APK | SAF с обработкой отсутствия/запрета picker; резервный `incoming-schedule.json` через app-specific storage. Один предпросмотр/подтверждение для обоих способов. |
| Целостность / откат | Один AtomicFile envelope с текущим/предыдущим календарями и SHA-256. Синхронизация, проверка записи, публикация после записи, подтверждаемый откат, восстановление проверенного резерва при повреждении payload. |
| Смена экрана после импорта | StateFlow + ключи календаря в Compose; реальный MainActivity-тест проверяет изменение видимой строки Аср и её восстановление после отката без перезапуска. |
| Сутки / год | Полные даты. Следующий год можно загрузить заранее; прежний меньший год обслуживает только свои даты. После полуночи — новый календарь; откат отвергает будущую версию. Нет данных — часы остаются, чужие времена не используются. |
| Семантика Фаджра | По умолчанию UNCONFIRMED: утром не показывается ложный следующий Зухр. PRAYER_START допускается только как подтверждённое правило источника. Учитывается собственная семантика нового года. |
| Часы / lifecycle | Europe/Moscow, минутный snapshot и отдельный секундный countdown. Resume и time/date broadcasts читают новый Instant; системная коррекция не накапливает ошибку таймера. |
| Offline | Нет INTERNET/ACCESS_NETWORK_STATE и сетевого клиента. Приватный календарь и настройки читаются локально. Закрытие/отмена импорта не применяет поздний результат и не блокирует табло. |
| HOME / восстановление | HOME + DEFAULT и LEANBACK, singleTask, fullscreen, KEEP_SCREEN_ON. Возврат HOME закрывает админ-экран. Есть системные настройки HOME/даты, chooser другого лаунчера и инструкция восстановления. Назначение HOME делает администратор. |

Админ-интерфейс на русском; переключатель языка относится к табло, включая предупреждения. Подписи мечети — редактируемые данные, их изменение не меняет календарь и Europe/Moscow. Вход пятью OK защищает от случайности, но не является аутентификацией.

## Фактические проверки

Linux, OpenJDK 17, Android SDK 35 / Build Tools 35; закреплённый toolchain из этапа 1. Выполнено:

```bash
JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64 ./gradlew \
  :app:assembleDebug :app:assembleRelease :app:test \
  :app:lintDebug :app:lintRelease :app:assembleDebugAndroidTest

git diff --check
```

**PASS:** Debug APK, unsigned Release APK, instrumentation APK, **121 выполнение тестов: 74 Debug + 47 Release**, без пропусков/падений. Общие сценарии действительно повторяются в обеих конфигурациях; это не 121 уникальный сценарий.

- 30 чистых тестов: модели, строгий JSON/UTF-8/размер/типы/дубли/полнота, високосный год, сезонные времена без нормализации, время/таймер/локали, Фаджр, граница события/года, режимы/углы и вход с пульта.
- 17 Android/Compose сценариев выполняются также в **Release**: настоящий MainActivity, D-pad, сохранение и восстановление, подтверждение/таймаут/recreate, все DisplayMode, импорт/предпросмотр/человеческое подтверждение/откат, обновление видимых строк, SAF URI, отказ неутверждённым данным, ошибки файлов, отмена блокирующего чтения, редактор подписи, HOME/permissions, SharedPreferences и прерванный AtomicFile.
- Дополнительные Debug UI-проверки: все 8 строк, отдельные время/countdown, отсутствие ложного Фаджра/времён без данных, скачок Instant, цвета четырёх углов реального Compose-поворота, lifecycle stop/resume/TIME_CHANGED.
- Рендеры двух тем: portrait/landscape/CW/CCW в 720p, 1080p и 4K; BOTH/TT/RU, fontScale 1.3 с масштабом приложения 115%. Проверяются размеры bitmap, видимость восьми строк и `hasVisualOverflow` у текстов табло.
- Lint Debug и Release: **0 ошибок, 10 предупреждений** в каждом — преимущественно новые версии зависимостей, target SDK и стилистическая рекомендация SharedPreferences KTX. Baseline/suppress не добавлялись; устаревшие debug-ресурсы и проблемы backup/banner исправлены.
- `apkanalyzer dex packages --defined-only` для Release: fixture/test-классы отсутствуют, `LocalScheduleRepository` присутствует. В Release нет встроенных времён молитв или остановленных демонстрационных часов.

CI запускает тот же набор сборок, тестов, обоих lint и instrumentation-сборку. Результат конкретного коммита виден в Checks Draft PR. Artifacts: `nur-islam-debug`, `nur-islam-release-unsigned`, `checks-and-screenshots`.

## Обнаружено и исправлено

- Исключение неоднозначного Фаджра в этапе 1 могло делать Зухр «следующим» утром. Теперь отдельный статус неопределённости, подтверждаемое правило и тест экрана.
- Запоминание данных только по дате оставило бы устаревший UI после импорта. Состояние календаря наблюдаемо и входит в ключи; проверены видимые строки до/после замены и отката.
- Граница года с заранее импортированным файлом не должна выключать ещё действующие даты. Добавлено строгое использование предыдущего меньшего года и отдельная защита отката будущего файла.
- После отмены/таймаута поворота меню должно вернуть D-pad-фокус. Это реализовано и проверено.
- Заблокированное чтение документа не должно удерживать админ-экран: отмена закрывает stream, отделяет устаревший результат и сохраняет доступ к табло.
- Стандартная AndroidViewModel-фабрика в Robolectric удерживала Application предыдущего тестового запуска. Явная фабрика текущего Application устранила смешение состояния тестов; прогоны Debug/Release изолированы.
- Lint обнаружил непомещённый в remember state новой UI-фикстуры: state вынесен из композиции, подавления lint не использовались.

## Что ещё требует реального подтверждения

1. **Официальный календарь:** ответственный утверждающий, источник и полнота, спор Иша 18:45/18:50, смысл Фаджра. В APK рабочий календарь не выдуман. Икамат, хиджра и Рамадан не вычисляются.
2. **Аппаратура:** модель/Android, направление монтажа, реальные пульт/overscan/шрифты, GPU, SAF/USB/ADB, HOME/default launcher, cold boot/reboot/AC loss, sleep/resume, CEC/питание. Instrumentation APK собран, но на ТВ/AVD в этой итерации не запускался; ограничение KVM предыдущей среды не выдаётся за аппаратную приёмку.
3. **Длительная работа и накопитель:** 72 часа и реальные отказы питания/флеш-памяти. Тест прерванной записи — моделирование, не эксперимент с питанием телевизора.
4. **Развёртывание:** постоянный ключ подписи у владельца, разрешение на установку и на выбор HOME, процедура возврата. ПО не делает скрытого принудительного kiosk/Device Owner.

Полная инструкция: [TV_OPERATIONS.md](TV_OPERATIONS.md). Эти пункты ограничивают полевой допуск, но не требуют сервера или пересборки APK для последующего утверждённого календаря.
