# Первый запуск Android TV: HOME / Device Owner / Lock Task

**Статус:** отдельное требование для следующего PR. Не входит в уже открытый PR #10 с исправлением сохранения календаря. Нельзя обещать универсальную установку в один клик на любом Android TV.

## Цель владельца

Установить APK на телевизор мечети и **без компьютера, ADB и ручного ввода команд** пройти понятный мастер настройки с пульта, чтобы после включения питания/перезагрузки телевизор открывал табло и, если доступно на прошивке, оставался в защищённом kiosk-режиме. Администратор должен уметь восстановить штатный HOME.

### Три разные возможности (не смешивать)

1. **HOME:** стандартная установка приложения по умолчанию для HOME. После обычной установки пользователь может подтвердить выбор через системную UI (Android 10+/API 29: проверка `RoleManager.ROLE_HOME`, `isRoleAvailable/isRoleHeld`, `createRequestRoleIntent`, с fallback к `Settings.ACTION_HOME_SETTINGS` или chooser). **Это реализуемо без ADB, только если телевизор позволяет менять HOME.** Нельзя незаметно назначить себя.
2. **Device Owner (DO):** *не обычное разрешение*. Нельзя стать DO после установки на **уже настроенном** устройстве нажатием в APK «Разрешить». Android требует provisioning в состоянии ещё не настроенного устройства, как правило после factory reset. При наличии совместимой прошивки возможен QR/zero-touch/другой поддерживаемый managed provisioning **без ADB**, но не в виде постинсталляционного системного разрешения. Некоторые Android TV и приставки не предоставляют этот механизм. Простая активация Device Administrator **не даёт DO**.
3. **Lock Task (настоящий kiosk):** разрешить DPC при наличии DO/других подходящих полномочий через `DevicePolicyManager.setLockTaskPackages`, затем стартовать `startLockTask()` только если `isLockTaskPermitted(packageName)` возвращает true. Без allowlist нельзя выдавать обычное screen pinning за полноценный kiosk.

Авторитетные документы:
- https://source.android.com/docs/devices/admin/provision (Device Owner только на unprovisioned)
- https://developer.android.com/work/dpc/dedicated-devices/cookbook (HOME через DPM, когда есть DO)
- https://developer.android.com/work/dpc/dedicated-devices/lock-task-mode (allowlist Lock Task)
- https://developer.android.com/reference/android/app/role/RoleManager (ROLE_HOME/запрос роли)
- https://developers.google.com/android/management/provision-device (QR/zero-touch при первоначальной настройке)

## UX: мастер первого запуска после установки APK

**Экран 1: проверка возможностей и состояния.** Определить версию Android, package, текущую HOME роль/предпочтительную активность, `DevicePolicyManager.isDeviceOwnerApp()`, `isLockTaskPermitted()` и активность lock task. По результатам — честно показать:
- «Можно назначить главным экраном» / «HOME недоступен на этой прошивке»;
- «Устройство управляется нашим приложением» / «Требуется управляемая первоначальная настройка»;
- «Kiosk доступен» / «Kiosk недоступен без управления устройством».

**Экран 2: HOME (основная доступная настройка).** Кнопка «Сделать Нур Ислам главным экраном» открывает **настоящий системный запрос** роли или настройки HOME. После возврата **повторно проверить состояние**, а не считать положительный результат автоматически. Возможность отказаться и продолжить обычный режим. Указать, что возврат после reboot/AC loss надо проверить на конкретном ТВ.

**Экран 3: Полный kiosk (дополнительный).**
- Если приложение **уже** DO (либо надлежаще allowlisted другим DPC): предложить включить/выключить Lock Task с подтверждением, **после проверки безопасного выхода** и списка допустимых экранов. DO может программно назначить свой HOME через `addPersistentPreferredActivity`.
- Если не DO: показать честную инструкцию «На уже настроенном ТВ это не выдаётся разрешением». Описать поддерживаемый первоначальный provisioning (только при положительной проверке устройства), необходимость сохранения данных перед factory reset; не начинать reset автоматически.
- Если provisioning неподдерживаем: оставаться в обычном HOME-режиме, не показывать ложное «Защищённый режим включён».

**Экран 4: проверка.** Проверяемая сводка HOME/DO/Lock Task, кнопка «Проверить возврат к табло», инструкция сброса HOME/выхода и отправки логов. Перечислить непроверенные аппаратные функции: reboot, AC loss, HDMI-CEC, TV sleep/ambient, overscan.

## Особенности реализации

- Обычная установка APK = **HOME мастер**; это не включает DO автоматически.
- Для поддерживаемой *отдельной* конфигурации «managed/dedicated TV» документировать либо provisioning нашего DPC компонента (DeviceAdminReceiver + необходимые provisioning hooks), либо установку/allowlist нашего APK в уже управляемом устройстве. Не создавать отдельную EMM платформу без нужды.
- **Перед фактическим DPC provisioning** проверить модель и Android TV firmware; у телевизора может не быть камеры/QR-читалки, managed provisioning UI или factory reset path; не обещать поддержку QR повсюду.
- Никаких обходов системы, постоянных Accessibility-автокликов, root/ADB-скриптов в релизном APK, использования сторонних привилегированных разрешений или попыток вызвать фоновые Activity в обход ограничений Android.
- Мастер не должен прерывать часы/табло при обычной работе; после первичной настройки не открывать его при каждом рестарте.
- Для опасных действий обязательны понятное подтверждение, возможность отмены и **проверенный путь восстановления**. Сначала убедиться, что админ может открыть настройки с пульта и выйти из Lock Task. Не «запирать» владельца навсегда.
- Не выполнять factory reset, назначение DO/Lock Task на рабочем TV без отдельного Owner GO.
- Все состояния и ошибки показывать в Release и тестировать отдельно от Debug.

## Проверки / приёмка

- [ ] APK с обычного установщика и первого запуска предлагает HOME, если системная прошивка поддерживает.
- [ ] Отказ от HOME не блокирует использование приложения.
- [ ] При отказе/ошибке HOME интерфейс сообщает реальный статус; проверка роли выполняется повторно.
- [ ] Device Owner **не изображается обычным разрешением**. На уже настроенном устройстве штатный сценарий не пытается стать DO.
- [ ] Lock Task включается только при настоящем разрешении/allowlist; иначе не запускает screen pinning.
- [ ] На управляемом тестовом устройстве есть сценарий безопасного входа/выхода Lock Task и восстановления HOME.
- [ ] На обычном ТВ без DO остаётся рабочий режим HOME + fullscreen + KEEP_SCREEN_ON.
- [ ] Тесты UI/system intents и API 26/29/35 по доступной среде; реальные системные диалоги и boot нельзя заменить Robolectric.
- [ ] Аппаратно: 3+ reboot, AC loss, screen standby, пульт, HOME chooser, режим полного kiosk и аварийный выход, 72 часа.
- [ ] Описан отдельный no-ADB provisioning путь **для подтверждённой модели**, если она это поддерживает.

**Не изменять текущий PR #10 ради этой цели**: отдельный Issue/PR после приёмки исправления календаря.

## Чего нельзя обещать

«Скачал APK → нажал Разрешить → приложение стало HOME + Device Owner + Lock Task на любом Android TV» **невозможно в рамках стандартной модели безопасности Android**. Реальный UX — простой in-app HOME мастер + отдельный управляемый provisioning при доступности платформы.
