# Постоянная подпись, установка и обновление

## Тестовые пакеты

- TV Debug: `dev.nurislam.tv.debug`, **Nur-Islam-TV-Debug.apk**.
- PhoneDebug: `dev.nurislam.tv.phone.debug`, **Nur-Islam-Phone-Debug.apk**.
- Release: `dev.nurislam.tv`, artifact **unsigned**; подписывает владелец своим production-ключом. В этой работе production-релиз не публикуется.

Оба тестовых пакета подписываются одним постоянным **тестовым** ключом. Его публичный
SHA-256 сертификата закреплён в [config/test-signing-cert.sha256](../config/test-signing-cert.sha256):
`52af1f59b0661ae514cd3b531ebe0ff91fb333a63138612932f84537fd880152`.
Ключ и пароль находятся вне репозитория. CI хранит их в repository secrets,
передаёт только отдельному шагу подписи доверенных веток этого репозитория и удаляет
временные файлы. Fork PR получает проверки сборки без доступа к постоянному ключу.
Не переносите production-ключ в этот тестовый процесс.

CI сначала собирает и проверяет код без секретов. Отдельный job подписывает только
два разрешённых applicationId и androidTest APK. Несовпадение с закреплённым сертификатом
останавливает публикацию совместимых обновлений. В artifacts нет ключей/паролей.
Рядом с каждым APK — SHA-256 файла, публичный `apksigner verify` и Android manifest badging.

## Первое обновление со старых CI-сборок

Ранее каждый CI-run создавал новый стандартный debug key. Последний ранее выданный
PhoneDebug имел сертификат `f247a94283b8d23f38c480d836af4d3bea8480694cd5c685748fdcf72077559d`,
который отличается от постоянного ключа. Android запрещает заменить его новым APK
поверх с сохранением данных: обычное нажатие выдаст конфликт подписи. Обхода без
старого закрытого ключа нет. Не удаляйте приложение ради устранения ошибки без подготовки.

Один раз перед переходом:

1. Сохраните исходные JSON/XLSX вне папки приложения.
2. Запишите/снимите экран с темой, ориентацией, масштабом, языком и подписями.
3. Запишите все правила икамата: молитва, режим/значение, дата действия, исключения,
   источник и подтверждение базы. Отдельно сохраните периоды/источники Рамадана.
4. На телефоне удаление старой **тестовой** копии и установка новой потребуют ручного
   восстановления этих настроек и повторного импорта. Если нет копий — не удаляйте
   приложение. Автоматическое извлечение приватных данных через APK с другой подписью невозможно.
5. На рабочем TV сначала согласуйте окно, выход из HOME/kiosk и отдельный план
   восстановления. Эта инструкция не разрешает удалять/обновлять H728/Xiaomi.

После перехода следующие опубликованные тестовые APK имеют тот же сертификат и
устанавливаются **поверх**, без удаления данных. Не меняйте вручную repository signing secrets.
Владельцу нужно сохранить защищённую резервную копию тестового keystore и пароля
раздельно от исходников; потеря обоих экземпляров ключа снова нарушит совместимость.

## Обычное обновление без ADB

1. Скачайте ZIP нужного artifact из зелёного CI нужного HEAD, распакуйте APK.
2. Сопоставьте пакет и сертификат с уже установленной копией; не используйте APK
   из постороннего источника. На компьютере: `apksigner verify --verbose --print-certs FILE.apk`.
3. Откройте файл штатным файловым менеджером. При запросе Android временно разрешите
   установку из этого источника. Выберите **Обновить**. Не выбирайте очистку данных/удаление.
4. После установки отзовите разрешение неизвестного источника. Откройте приложение,
   проверьте настройки, год/источник календаря, икамат и Рамадан.
5. Если Android сообщает о конфликте подписи, понижении версии или несовместимом APK,
   остановитесь. Сохраните данные и выясните причину. Не подписывайте каждый APK новым ключом.

Версия 0.3.0; локальный default versionCode=3. CI присваивает возрастающие коды,
а для проверки обновления собирает две последовательные версии с одинаковым исходным кодом.
Проверяется установка `-r` на одноразовых эмуляторах и неизменность приватных данных.
CI artifact не является production-публикацией.

## Локальное воспроизведение подписи

Соберите два поколения тестовых APK и положите их в `base/tv.apk`, `base/phone.apk`,
`updated/tv.apk`, `updated/phone.apk`. Параметр Gradle `-PnurIslamVersionCode=NUMBER`
позволяет явно задать код. Затем:

```bash
python3 scripts/sign-test-apks.py --input TEST_BINARIES --output DISTRIBUTIONS \
  --keystore /secure/outside-repository/nur-islam-test.jks \
  --password-file /secure/outside-repository/test-password
```

Скрипт откажет ключу/паролю внутри репозитория и production applicationId. Пароль
передаётся Android apksigner через окружение дочернего процесса, не в аргументе командной
строки. Не включайте shell tracing и не публикуйте содержимое секретных файлов.
Для production-подписи используйте отдельный ключ владельца по [TV_OPERATIONS.md](TV_OPERATIONS.md).

Основания: [Android app signing](https://developer.android.com/studio/publish/app-signing),
[apksigner](https://developer.android.com/tools/apksigner). Совместимая подпись необходима
для обновления; APK с более низким versionCode обычным установщиком не ставится поверх.
