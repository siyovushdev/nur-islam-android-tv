# Задача Codex — Этап 1: каркас нативного Android TV APK

Репозиторий: `siyovushdev/nur-islam-android-tv`, ветка `main`.

Сначала **прочитай**:
- [ТЗ](TZ_DRAFT.md);
- [формат расписания](SCHEDULE_FORMAT.md);
- [дизайн-спецификацию](../design/DESIGN_SPEC.md) и [SVG-схему](../design/REFERENCE_LAYOUT.svg);
- [план разработки](ROADMAP.md).

**Решение:** Google Stitch отменён; визуальное направление утверждено по ранее созданному изображению. Оригинальный PNG будет дополнительно добавлен владельцем при необходимости. SVG — доступный в репозитории ориентир для блоков; не используйте SVG как единый растровый UI на экране.

## Требуется в этом PR

1. Создать минимальный рабочий Gradle Kotlin DSL Android TV проект, один модуль `app`.
2. Kotlin + Jetpack Compose. **Не использовать HTML, WebView, JavaScript, frontend/web tooling**. Без сервера.
3. Manifest для TV (`LEANBACK_LAUNCHER`, без обязательного сенсорного экрана), работа с пультом D-pad; уместные темы/fullscreen.
4. Стартовый `PrayerBoardScreen` с нативными Compose-компонентами по `design/DESIGN_SPEC.md`: шапка, огромные часы, дата, отдельно ближайший намаз/точное время/countdown, 8 строк таблицы. Использовать пока **явно демо**-времена из примера; видимую пометку TEST/DEMO. Отображать mock только в debug/demo; релиз не должен показывать неутверждённые времена как настоящие.
5. Простая структура `ui/`, `model/`, `data/`, `domain/` внутри одного модуля. Нет DI-фреймворка/Room/сервисов без обоснования.
6. Часы обновлять корректно относительно `Europe/Moscow`; при перезапуске и переводе системного времени экран корректно пересчитывается. Не обновлять весь экран каждую секунду без причины.
7. Сделать первичную поддержку разных окон: не фиксировать layout на 1080 px; вынести выбор `DisplayMode` (`AUTO`, `PORTRAIT_NATIVE`, `PORTRAIT_ROTATE_CW`, `PORTRAIT_ROTATE_CCW`, `LANDSCAPE`) и простой диагностический переключатель для debug. **Вертикально установленный 1920×1080 ТВ может оставаться landscape для Android.** Проверить математически правильное преобразование logical 1080×1920 ↔ physical 1920×1080 и отсутствие обрезки, не угадывать сторону поворота. Если в первом PR качество полного rotate-механизма не удаётся подтвердить — честно оставить отдельным этапом с тестами, а не маскировать проблему.
8. Добавить unit-тесты для чистых функций выбора режима, времени/форматирования и моделей; по возможности UI screenshot previews для portrait и landscape.
9. Проверь сборку и тесты, запиши фактические команды и результаты. Если Android SDK в среде отсутствует — не утверждать, что build PASS; описать препятствие.

## В этом PR НЕ делать

- Реальный парсер полного Excel и импорт расписаний (следующий этап).
- Принимать Иша 18:45/18:50 или значения икамата как утверждённые.
- Режим Device Owner / kiosk / принудительное открытие Activity из фона.
- Облачную синхронизацию, Room и ненужную multi-module архитектуру.
- Перерисовывать готовый дизайн как одну картинку: часы/тексты/времена должны быть нативными и изменяемыми.

## Приёмка

- Исходники APK и `./gradlew :app:assembleDebug`; доступные тесты.
- Стартовый экран читается, соответствует палитре и структуре референса.
- 8 строк, отдельный countdown, корректные татарские/русские строки.
- Доступны портретный и горизонтальный превью/режим; физический поворот предусмотрен без заведомо некорректных решений.
- Создать отдельную ветку и **Draft PR**, не merge, не менять `main` прямо.
- Отчёт: кратко «изменения / проверки / ограничения / следующий шаг»; ссылки на PR и снимки экранов.
