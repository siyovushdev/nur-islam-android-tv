# План разработки (Codex)

Принцип: **одна небольшая завершённая задача → тесты → Draft PR → проверка владельцем → merge**. Не разрабатывать сложную платформу заранее.

| Этап | Результат | Условие завершения |
| --- | --- | --- |
| 0. Подготовка | ТЗ, подтверждение источника времён, модель устройства, дизайн Stitch | Закрыты критичные вопросы по данным и оборудованию |
| 1. Скелет APK | Native Kotlin/Compose Android TV app, Gradle, настройки сборки | Сборка и запуск на эмуляторе/устройстве |
| 2. Данные/время | Импорт годового календаря, Kotlin engine, unit-тесты | Сверка с подтверждённым источником; 2027/29.02/переход суток не дают неверных данных |
| 3. Табло | Реализация утверждённого дизайна Compose | Хорошая читаемость, корректные состояния и D-pad навигация |
| 4. Настройки | Настройки мечети и икамата, валидируемое обновление расписания | Перезапуск не сбрасывает конфигурацию, нет выдуманного икамата |
| 5. TV launcher | HOME/kiosk по результатам исследования устройства | Автозапуск/восстановление подтверждены на целевом ТВ |
| 6. Приёмка | Реальные перезагрузки, offline, 72 часа, журнал | Проверен сценарий установки, эксплуатации и возврата к заводскому Launcher |

## Порядок работы с Codex

1. Каждая задача — отдельный GitHub Issue с критериями готовности.
2. Codex изменяет код в своей ветке, сообщает конкретные файлы и результаты тестов, открывает Draft PR.
3. Нет автоматического merge без решения владельца.
4. Если устройство не поддерживает требуемый kiosk/HOME, не скрывать ограничение: сначала согласовать аппаратное решение.

## Не делать в первой итерации

- Встраивать HTML/WebView или переносить JS из референса.
- Делать сервер, облачный кабинет, рекламу, мультимедиа или телеметрию без требования.
- Автоматически выводить «официальные» времена из непроверенного астрономического калькулятора.
- Добавлять фоновые службы только ради удержания экрана, не проверив штатные механизмы Android TV.
