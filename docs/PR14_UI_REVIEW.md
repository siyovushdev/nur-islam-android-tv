# PR #14: импорт и положение табло

Проверка выполняется в `codex/phone-debug-preview`, поверх PR #13. H728 не используется, HOME/политики не меняются. APK остаётся отдельным пакетом `dev.nurislam.tv.phone.debug`.

## Импорт

- Вместо одинаковых карточек: «Проверка расписания», источник/год/число дней и информационная таблица восьми значений «Было → Из файла». Времена отображаются как прочитаны; таблица не содержит click-actions.
- Checkbox имеет состояния checked/unchecked/disabled. Основная кнопка золотая только после подтверждения; до него она серая и недоступна. Отмена — отдельная второстепенная кнопка.
- На телефоне таблица и длинные метаданные прокручиваются отдельно от закреплённых действий. На TV ↑↓ выбирают действия, ←→ прокручивают информацию, OK выполняет, BACK отменяет. Начальное выделение — отмена; фокус обозначен рамкой.
- После сохранения — «Расписание применено», источник, год и количество дней, отдельные «Вернуться к табло» и «К расписанию».
- `approved=false` остаётся неприменимым. Явные метки TEST / ТЕСТ / synthetic / demo / макет в **источнике** помечают тестовый набор и блокируют применение также при противоречивом `approved=true`. Отсутствие такой метки не доказывает подлинность. Конвертация Excel сама по себе не является утверждением. Для уже сохранённых тестовых источников на табло показано предупреждение.
- Парсер, восемь времён, календарные расчёты и проверки репозитория не изменены. Никакого Debug-обхода утверждения нет.

## Измерение табло

Симметричные layout-insets — 4% сверху/снизу: 76,8 px в логическом 1080×1920 и 43,2 px в 1920×1080. Сам `RotatedBoard` не смещает координаты: обратное преобразование снимков CW/CCW даёт те же границы, что portrait.

Однако painted bounds содержимого асимметричны: полумесяц, пустоты в блоках и наличие/отсутствие нижнего орнамента не совпадают с границами layout. Архитектурная рамка намеренно выходит за верх и продолжается снизу; её дисбаланс отделён от содержимого **вычитанием отдельного рендера неизменного фона**. Измерен bbox различающихся RGB-пикселей с порогом 12/255, без служебной подписи/демо-баннера. Это баланс видимых границ, не оценка центра тяжести каждого символа.

| Макет | Верх/низ до, px | Верх/низ после, px | Поправка содержимого |
|---|---:|---:|---:|
| Elegant portrait / CW / CCW | 82 / 112 | 97 / 97 | +15 px |
| Classic portrait / CW / CCW | 82 / 179 | 131 / 130 | +48,5 px |
| Elegant landscape | 48 / 69 | 59 / 58 | +10,5 px |
| Classic landscape | 48 / 83 | 66 / 65 | +17,5 px |

Portrait-значения относятся к логическим 1080×1920, landscape — к 1920×1080. Поправка масштабируется тем же коэффициентом, что исходный макет; изменена только позиция foreground, без изменения размеров/весов блоков, архитектурного Canvas или `RotatedBoard`. Округление позиции даёт до 1 px разницы отступов. Служебная подпись внизу добавляет собственные видимые пиксели и не используется для центрирования основной композиции.

Для обеих тем, portrait/landscape/CW/CCW и 85/100/115% измерения одинаковы; тест проверяет разность верхнего/нижнего отступов ≤2 px, полное попадание восьми строк в окно. Дополнительно матрица 720p/1080p/4K и fontScale 1,3 проверяет отсутствие текстового overflow при всех трёх масштабах приложения.
