# Нур Ислам — Android TV табло времени намаза

Нативное Android TV приложение для настенных экранов мечети «Нур Ислам» (Казань). Показывает текущее время, дату, расписание намазов и следующий намаз. Должно работать без постоянного интернета и самостоятельно открываться после включения устройства там, где это поддерживает прошивка.

**Статус:** этап 1 завершён — [PR #8](https://github.com/siyovushdev/nur-islam-android-tv/pull/8) принят и слит в `main`. Далее — единая цель рабочего MVP: импорт расписания, две темы, настройки с пульта и подготовка HOME/autostart. Утверждение реального календаря и проверка ТВ ещё впереди.

## Принципы

- Только **Kotlin + Jetpack Compose / Android SDK**. Никакого HTML, JavaScript UI или WebView в приложении.
- Дизайн: утверждённая художественная концепция + схема в SVG → нативная реализация в Compose. Stitch не нужен.
- Приоритеты: точность расписания → надёжность экрана → читаемость с расстояния.
- Основной сценарий: ТВ с физическим разворотом 90°, системное разрешение 1920×1080. Также нужен режим обычного горизонтального ТВ; пользователь выбирает режим отображения.
- Администратор меняет годовой календарь через импорт проверенного JSON без пересборки APK; отсутствие интернета не останавливает табло.
- На старте один app-модуль, без собственного сервера и сложной инфраструктуры.
- Расписание offline-first, с привязкой к конкретному году и подтверждённому источнику.
- Автозапуск: оценить HOME/kiosk для **конкретного** ТВ/приставки; один BOOT_COMPLETED не гарантирует открытие Activity.

## Что нужно согласовать до использования в мечети

1. Реальная модель Android TV или приставки; версия Android и ориентация ТВ (16:9 или 9:16).
2. Источник времени Иша: в исходных HTML и Excel на 142 датах разница 5 минут.
3. Значение колонки «Мәчеттә укыла» и отдельно утверждённое время икамата для каждого намаза.
4. Кто утверждает очередной годовой календарь, хиджру и даты Рамадана.

**Важно:** исходные HTML и Excel служат референсами и данными для проверки, а не кодом, который будет встроен в APK.

## Разработка

Главный ориентир следующего этапа — [CODEX_MVP_GOAL.md](docs/CODEX_MVP_GOAL.md). Codex доводит **программный MVP** до проверенного результата в отдельной ветке, а не останавливается на одной мелкой задаче. Каждый merge, установка на рабочий ТВ и production-релиз требуют решения владельца.

В MVP обязательны темы **Elegant** и **Classic**; переключение и конфигурация экрана (включая ±90°) доступны на пульте в **Release**, а расписание заменяется импортом подтверждённого годового JSON без сборки APK.

## Этап 1: нативный каркас

Один модуль `app`, Kotlin + Jetpack Compose, minSdk 26. HTML/WebView и сетевых разрешений нет. Демо-расписание из PNG доступно **только в debug** и только на полную дату **2026-10-23**. Оно не является утверждённым календарём. Release собирается без класса демо-репозитория и показывает часы, восемь строк без времён и сообщение об отсутствии расписания.

Для сборки нужны **JDK 17**, Android SDK Platform 35 и принятые лицензии SDK. Путь SDK задаётся Android Studio, `ANDROID_HOME` или `local.properties` (не коммитить).

```bash
./gradlew :app:assembleDebug :app:assembleRelease :app:test :app:lintDebug
```

Debug APK: `app/build/outputs/apk/debug/app-debug.apk`. Release APK пока unsigned; для эксплуатации он ещё не предназначен. Если текущий `JAVA_HOME` указывает на JDK 11, сначала выберите JDK 17.

### Режим экрана и пульт

В debug нажмите **MENU** на пульте (или **M** на клавиатуре). D-pad выбирает пункт, CENTER/ENTER применяет, BACK закрывает меню. Настройка `DisplayMode` сохраняется в SharedPreferences и восстанавливается после перезапуска.

- `AUTO`: выбирает portrait/landscape по окну; физический поворот панели не угадывает.
- `PORTRAIT_NATIVE`: ОС уже предоставляет портретное окно.
- `PORTRAIT_ROTATE_CW`: весь портретный layout поворачивается на **+90° по часовой стрелке** в системном окне.
- `PORTRAIT_ROTATE_CCW`: весь layout поворачивается на **−90°**.
- `LANDSCAPE`: часы и следующий намаз слева, восемь строк справа.

Для повёрнутого 1920×1080 окна дочерний Compose layout сначала измеряется как **1080×1920**, затем центрируется и поворачивается. CW отображает `(x,y)` в `(1920−y,x)`, CCW — в `(y,1080−x)`. Направление нужно выбрать на установленной панели: приложение не определяет его по датчикам. Меню находится в том же повёрнутом контейнере. UP/DOWN всегда перемещают выбор вверх/вниз для пульта, который держат вертикально. Дополнительно поддерживаются повёрнутые оси: в CW клавиша LEFT перемещает вниз по меню, в CCW — RIGHT; обратные клавиши перемещают вверх.

Пункт «Демо: 23.10.2026, 14:20» останавливает debug-часы для сравнения с PNG. На экране появляется явная надпись об остановке часов. Пункт «Показать живые часы» возвращает системное время. Этот режим не сохраняется при перезапуске. Рабочее табло использует системный Instant с отображением в Europe/Moscow; хиджра и икамат не вычисляются.

### Простая структура

- `model/`: восемь исходных полей, день с полной датой и метаданные источника.
- `data/`: `ScheduleRepository.day(LocalDate)`, политика approved/demo и разные реализации для debug/release.
- `domain/`: выбор следующего подтверждённого по смыслу события, форматирование и геометрия экрана.
- `ui/`: Compose-табло, Canvas-декор, измерение/поворот, часы с учётом lifecycle.

Репозиторий расписания отделён от UI. На этапе 2 его заменит реализация поверх валидируемого локального JSON в приватном хранилище приложения: SAF → проверка всего года в памяти → подтверждение → атомарная замена с резервной версией. **Парсер, импорт и запись файла пока не реализованы**; контракт не выдаёт их за готовую функциональность. Икамат останется отдельным набором настроек.

`fajrInMosque` сохраняется как исходное поле и показывается в таблице, но исключён из расчёта «следующего намаза», пока смысл не подтверждён. Сухур, восход и зенит также не используются как следующий намаз. После Иша используются только реально имеющиеся данные следующей полной даты; вчерашние/прошлогодние времена не подставляются.

Большие часы и таблица зависят от минутного snapshot. Секундное состояние читает только countdown. При возобновлении Activity и изменении системного времени берётся новый Instant, а не уменьшается накопленный счётчик.

Проверки Compose выполняются локально через Robolectric/Skia без обязательного эмулятора; PNG сохраняются в `app/build/screenshots/`. Те же базовые UI-тесты входят в instrumentation APK.

Compose-превью находятся в `app/src/debug/java/dev/nurislam/tv/BoardPreviews.kt`. Проверки и ограничения этапа — в [отчёте](docs/STAGE_1_REPORT.md).
